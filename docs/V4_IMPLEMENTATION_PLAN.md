# GitRadar V4 完整改造实施计划

> 2026-10-21 最新决定：用户要求简化快速交付，生产零模型。本文件保留原探索设计；本次发布范围以 [README](../README.md) 和 [当前状态](evaluation/V4_ACCEPTANCE_STATUS.md) 为准，原模型、真人与长期观察门槛不再阻塞此次简化发布。

> 执行时按任务使用 superpowers:subagent-driven-development 或 superpowers:executing-plans。2026-10-20 用户确认开始执行；工程、读者任务和持续运行效果分别记录。

**执行进度：** 下文任务清单保留原验收设计，不能据未勾选项重复开发；当前已实现内容、失败证据与未验证门槛以 [V4_ACCEPTANCE_STATUS.md](evaluation/V4_ACCEPTANCE_STATUS.md) 和文末“本轮交付状态”为准。

**目标：** 让普通中文用户在两分钟内找到相关开源项目，理解用途和必要条件，并进入正确的官方获取路径；在免费自动化运行中持续产生有证据的新推荐。

**架构：** 保留现有静态 Pages、Actions 与历史快照，用批量观测、官方证据、中文内容、推荐资格和静态生成分离职责。默认首页改用通过内容门槛的推荐池，完整候选与增长榜保留；新增契约通过兼容层连接 V3.3。

**技术：** Python 标准库、原生 HTML/CSS/JavaScript、GitHub REST/GraphQL、现有 GitHub Actions 和 Pages。

**设计依据：** [GitRadar V4 产品改造方案](V4_PRODUCT_DESIGN.md)。本文所有验收引用该方案第 8–10 节，不以测试数量代替产品效果。

## 全局约束

- 完全免费优先，不使用付费 AI 或翻译，不要求新增个人密钥、购买硬件或常驻本地模型。
- 保留 history.json 所有已有项目、日期键和非当日值；当天只更新成功观测，不伪造缺失日期。
- 保留现有候选与 radar_saved 收藏；新字段增量接入，旧 JSON 有明确回退。
- Python 函数尽量不超过 30 行；严格类型、无静默吞错，优先标准库，不引入前端框架。
- 报告中的“已核对资料”与“实际试用”分开；重要用途、平台、费用、前提和获取入口都有证据。
- 修改数据结构前先固定消费者与迁移测试。所有真实采集先写隔离目录，通过整批校验后进入正式提交。
- 本轮按一个完整范围实施，允许内部多个可回滚提交，不用缺项版本代替最终交付。

## 审查重点

1. 英文提到示例、被集成的软件、开发目标或不支持的平台，不能变成本项目能力。
2. 中文编辑仍在而底层证据改变、资产删除、仓库改名时，旧资格不得自动继承。
3. API 返回 200 但包含 GraphQL 错误、部分节点为空、304、限流或跨 UTC 日期时，不得制造成功观测。
4. 新旧页面与 JSON 混用、静态 HTML 与动态数据批次不同时，不能把未知状态补成已审核。
5. 少数人工种子和已知案例不能替代盲测、未来未见项目、真实读者及连续运行的验收。

## 文件和数据边界

保留 collect.py 作为命令入口、discovery_stats.py 作为统计边界。新增 gitradar/ 包承载 github_client.py、observations.py、content.py、recommendations.py、site.py、validation.py、models.py；不把所有新逻辑继续堆入 collect.py。

web/templates/ 保存首页、场景、详情和探索模板，web/assets/ 保存原生交互和样式；生成产物继续适配当前 Pages 根目录发布。首页和合格项目详情预渲染，完整候选保留按需读取数据的能力。

新增数据为 evidence.json、curation.json、recommendations.json；现有 projects.json、summaries.json、history.json 按设计迁移。评测来源与结果放在 tests/fixtures/ 和 docs/evaluation/；盲测输入与标签由独立评审保管，不进入实现者工作区。冻结实现代码提交、完成首次盲评之后才归档，不能在冻结样本时提前公开答案。

models.py 先固定下列类型，生产函数只消费这些类型：

| 类型 | 必需信息 |
|---|---|
| RepositoryRef | node_id 或初始化时的仓库名、显示名、原 history_key |
| Observation | 实际观测时间、Star、仓库状态、身份，成功或失败及原因 |
| ObservationBatch | 按身份关联的观测、批次时间、部分错误和真实消耗，HTTP 成功不代表全批成功 |
| EvidenceRef | 官方 URL、章节或资产标识、来源版本／哈希、核对时间 |
| EvidenceBundle | 官方原始片段及引用、读取状态、可复用缓存 |
| ProjectFacts | 用途证据、交付形态、多场景、目标设备、使用路径、前提、许可／费用／服务依赖，各字段关联 EvidenceRef |
| ContentRecord | 中文用途、受众、条件、理由、review_kind、编辑结论与绑定版本，另行计算的 effective_status 和失效原因 |
| Eligibility | 是否合格、未通过原因、可展示场景和设备、失效条件 |
| RecommendationFeed | 当前至多 20 个推荐、版本、批次、首次推荐日期及轮换记录 |
| Snapshot / BuildManifest | 批次、schema、各输入版本和产物哈希，用于生成及一致性校验 |
| Budget / Usage | 搜索、REST 请求、GraphQL 点数、重试和余量，全部记录真实消耗 |
| ValidationReport | 是否允许提交、阻断错误、警告与验证项，未验证不能默认为通过 |

## 执行依赖与交付节奏
