## 冻结版新增工程问题

### P1：官网种子与生产文本抽取不一致，首次复核无谓撤销资格

位置：`gitradar/sources.py:100-116`、`gitradar/github_client.py:webEvidence`、`gitradar/evidence.py:60-70`，以及官网种子ref的 `text/source_hash`。

2026-10-20实取 `https://keepassxc.org/download/` 返回200。种子来源文本长度3531、hash为 `7aba283ab2d3f84619cf6d61a1323405aa8bfc56b83fb3c721fdad93c10e7f34`；生产 `visibleSourceText` 为3590字符、hash为 `30769b03fa993157065e8489612a446cde9c316c631cacf1654430ce6f364ee2`。实际差异包括：

- 种子 `Requires MSVC Redistributable`，生产 `Requires\nMSVC Redistributable`。
- 种子 `KeePassXC for Windows 10 / 11`，生产在Windows之后换行。
- Apple Silicon等内联HTML文字也被拆成多行。

可见文本内容仍支持相同安装条件，但旧片段不是生产文本的子串。将这份真实结果通过 `webEvidence → mergeEvidence → deriveFacts → resolveContent`，同一curation从 `eligible=true` 变成false，原因为requirements_1/path的 `changed_evidence` 和 `context_changed`。这是来源采集格式的跨组件不一致，不是网页声明了新前提。

应统一种子生成与生产复核的文本规范，并按同一规范重新核对、绑定片段和上下文哈希；不能通过HEAD刷新正文日期或忽略真正的上下文变化来绕过。影响范围可能包含其他官网片段，需在真实采集批次检查实际撤资格原因及推荐数量。本报告未擅自扩大为所有官网必然失败。
