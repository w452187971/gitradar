本次实际官方服务端通过结构 canary，六项输出均具有要求的字段对象，证明嵌套 schema 约束已生效。整个诊断耗时 153.479 秒，server RSS 峰值 3,026,252 KiB。常规离线校验同时要求 unknowns 与空值一致；该项仍只有 2/6 通过，且这两项均全部弃答。其余四项的非空字段同时被列入 unknowns，不能直接接入内容流水线。不能把 2/6 表述为语义准确率。

本次协调者作资料检查，属于 AI 代理检查，不是真人评阅或实际试用。观察到的具体问题包括：

- TranslucentTB 将下载入口的域名与路径拼成来源中不存在的 URL；费用引用 `free (as in speech)`，不能单靠这句支持零价格，虽然另一来源确有免费下载声明。
- AdGuard Home 的平台列表及完整 Wiki 地址不在所选引用中；部分引文将不连续原句连缀后输出。`网络环境` 也不足以概括已给出的设备配置及 DNS 屏蔽限制。
- fd 把英文来源译成中文放入 source_quote，并输出来源没有声明的费用信息。
- Transformers 将 ref_id 当成 source_quote，平台仍混入 Python/PyTorch 依赖，部分 value 未按要求生成中文。
- 英语资料集合正确避开第三方 App 的功能与入口，但连标题有支持的资料下载用途也全部弃答，不能据此认为用途覆盖达标。
- 缺来源控制八字段均为 null，较首轮改善；它只是一个开发控制，不能外推总体拒答能力。

当前结论仍为不通过。结构约束解决了形状问题，不能证明用途、主语、条件与入口可靠；每维断言不足 30，完整效果准确率仍未验证。

下一诊断将让程序绑定原始来源、计算可由空值直接得出的 unknowns，让模型专注于中文事实与来源选择，并评估已核对许可和固定版本的官方 4B GGUF。协议及模型同时变化，后续只能称为新方案开发验证，不能当作仅参数规模变化的严格对照。生产数据、推荐和 Pages 仍不使用实验输出。
