# 下一阶段输入构建（尚未实施／待技术验证）

建议先把“一次生成八字段”缩为“程序限定来源角色，模型只表达一个有证断言”。可能同时减少错主语和长上下文成本，但尚未验证；六例仍是整理片段，不能代替真实生产builder端到端输入。无论8B结果如何，都不新增对旧六例的试验，不覆写curation。

**当前实现边界。** 生产`pipeline.resolveProjects`仅调用`deriveFacts`与`resolveContent`，没有接入模型。前者读取已有结构化facts或有限模板，后者合并编辑内容并检查资格；它们均不独立证明中文语义正确。现有探针只评估固定片段，尚无本文的InputPacket、Draft或生产转换层。本文是下一阶段技术冻结基线，不把已有开发授权改成额外用户审批；冻结前仍需明确契约和验证材料。

**来源先分职责。** 核对node_id后的metadata.description只提供“该仓库如何自述”的用途候选；清单/集合关系必须原样保留，不能改成所列第三方应用功能，也不推受众/平台/费用。身份确定不证明描述真实、条件完整或中文忠实；完整description也不等于完整项目资料。LICENSE/SPDX继续当前许可门槛，不从开源推免费，许可标识、变体与适用范围不能让模型改写。拟保留Release的release_id/tag/prerelease和asset_id/browser_download_url，限定版本状态与资产入口；URL只取实际对象。资产名/后缀中的OS最多是该资产的线索，不能推导整个项目的全部兼容平台或安装方式，latest不替代已选Beta。当前`evidenceRefs`的Release文本只保存body/tag_name/assets，不能假称已有release_id/prerelease结构契约；缺少原响应字段时必须记缺失，补齐归档与适配属于拟新增能力。

**README补条件，不凭标题授权。** 现有`readmeSections`只返回扁平的标题/正文对，不保留父标题、行号或字节位置，并会将一级标题统一为introduction。带层级与精确位置的候选索引是拟新增能力，不能由现有section字段猜出。安装节需保留完整原文和关联的系统要求、警告、否定、表格/脚注、外部资料身份。Installation标题、依赖命令或同域URL都不能证明“本项目获取方式”。第三方/示例/比较不进入主项目字段；归属不清即unknown。无法确认跨段条件关联或缺少被引用外部资料时，不标覆盖完整，也不只截取安装节；完整源归档不能替代实际送入模型的必要上下文。通用程序规则不能证明所有跨段关系和条件完整，4B relation也只是未核模型判断，不能改名为确定事实。

**模型仅表达。** 一个经角色约束的候选断言包输出中文text或null及原assertion_id；不选URL、不补费用/平台、不推受众、不合并八字段。角色约束不等于断言已经语义验证，结构值程序原样绑定也只保证没有被模型改写。用途可先表达完整description；涉及限制时送入完整关联上下文，不能只翻译肯定句而藏相邻条件。使用固定实际模型/runtime对应的tokenizer，对真实chat模板、全部消息及特殊token计数，并预留输出预算；溢出/来源不全/歧义分别记录原因，不裁限制。无效raw、超时/截断保留失败，不能改null后记正确拒答；预检失败未发推理也保留在预先冻结的项目分母中。另列调用级失败与耗时，多次窄调用不能增加独立项目数或充当更多独立语义断言。多次窄调用可能更慢，仍须固定整批CPU/时间预算实测。

**adapter独立契约。** 拟定buildInput(bundle,identity,sourceArchive,policyVersion,budget)→InputPacket：sourceArchive是显式、只读、按哈希寻址的冻结来源，不隐式联网；候选含assertion_id/field/source_role/subject_status、原值、完整source ref/hash、位置/上下文边界、覆盖状态/unknown原因。完整源单独存档；模型包避免重复正文，但必须包含本次断言所需的完整关联上下文，不能只给文件引用或旧片段。express(packet)→Draft：保留raw、模型/模板pin、token/耗时/失败，中文一律semantic_pending。两者不返回ProjectFacts、不写bundle.facts/curation，不调用deriveFacts/resolveContent。未来显式转换层需要独立验收，不能把Draft强转为FactClaim或将subject_status/覆盖标志直接当作complete=true；特别是当前结构化facts复制逻辑主要检查ref存在，并不验证语义。转换后仍须保留既有FactClaim(value/ref_ids/complete)契约、关键未知与全部资格检查；不冒充automatic_template，不改变curation优先级和发布门槛。

**先回放builder。** 可复用现有标准库、GitHubClient身份/缓存与evidenceRefs解析、本地GGUF接口，无需先引入框架；但完整响应归档、层级/位置索引及包构建尚未实现。现有refs的content_hash可能只是片段哈希，不能一概冒充全文source_hash；HTML须固定规范化版本，保留原始字节与规范化全文的各自哈希。冻结公开真实metadata/README/选定Release与资产响应、身份/URL及无凭据缓存状态、字节/hash、来源许可/版本、政策、时间/预算和失败清单，先回放“响应→bundle→packet→draft”，核对输入不变与curation不被覆盖。只有未来转换层另经验收后，才能扩展到“隔离facts/内容”，即使字段类型符合也不代表可推荐。当前材料能否覆盖完整条件、资产和缓存分支尚不确定，缺失须列明，不能用整理六例填充或称作端到端评估。独立离线机器翻译只列未来表达器候选；当前无现成依赖，官方许可、中文/否定保持及CPU预算均待另立评估。

**准入仍分两层。** 程序可核对身份匹配、白名单、字节/hash绑定、原URL、覆盖标志的传递与预算失败策略；不能证明该标志的语义成立、资料足够、中文蕴含、条件完整或读者理解。绑定quote不算准确率。政策、代码、开发输入与评估方法冻结后，必须用未参与设计的独立项目组验证主项目/依赖/第三方、否定/条件遗漏，固定项目分母并单列未知、无来源、预算溢出与超时；各维有效断言不足30仍为未验证，不能以多次调用凑数。旧六例是已反复查看的开发材料，不是盲评，也不能证明原始响应到生产输出的端到端效果。独立AI语义审核须明确标注，不能代替后续中文用户对用途与门槛是否清楚的验收。不能以覆盖少为由放宽许可、路径、关键未知或既有准确率门槛来凑推荐；未达标只供人工编辑草稿。
